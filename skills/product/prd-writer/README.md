# prd-writer: Product requirements document (PRD) writer

Turns a feature idea, user feedback or research notes into a problem-first PRD with jobs-to-be-done and prioritised requirements.

| | |
|---|---|
| **You give it** | A feature idea, user feedback, interview notes, research notes, support tickets |
| **You get back** | A PRD: problem statement, target users and JTBD, goals and non-goals, success metrics, must/should/could requirements, user flow, risks and open questions |
| **Method** | Problem framing before solutions, Jobs-to-be-Done, MoSCoW prioritisation |
| **Search terms** | PRD template, product requirements document, how to write a PRD, jobs to be done, MoSCoW prioritization |

It always starts by asking what you're trying to achieve and what you already have, then works through fixed steps. Every claim is traced to your material or labeled as an assumption.
